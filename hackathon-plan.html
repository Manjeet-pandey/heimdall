1. What I'm building

A supervisor for AI agents I don't fully trust. Each agent runs in a sandbox, and every move it makes on the network passes through one checkpoint that checks it, records it, and blocks it if it's off-script. Agents never hold real keys. Unknown moves are judged by Muse Spark; when the Meta API is down the checkpoint fails closed.

  • Who it's for: a solo dev running a coding or ops agent with production keys (GitHub, cloud, Stripe). Honest note: this is not my own daily pain — I don't run 24/7 agents. It's a security building block I think is cool and judges can test in 5 minutes.
  • Illustrative leak cost (example, not mine): e.g. OpenAI key with $50/mo hard cap; GitHub token with repo write; rotation ~2h. Video states these as scenario numbers, not my bills.
  • Install: docker compose up, under 5 minutes, timed on camera.
  • The line: "A coding agent read a poisoned GitHub issue and tried to steal keys. Here's where it got stopped."

Sandbox

  • Fails closed. Agents sit on a Docker internal: true network with no DNS. Anything that skips the proxy (QUIC/UDP, direct DoH, IPv6) has no route.
  • File policy, deny by default. An agent sees only what's mounted for it: read-only or read-write, everything else invisible. Non-root user, read-only root filesystem. 
    coder:
  files:
    read_only:  [~/notes]
    read_write: [~/agent-work/coder]
  network: learned allowlist
  • Trusts only my CA. mitmproxy CA in the image trust store, plus REQUESTS_CA_BUNDLE / SSL_CERT_FILE (Python) and NODE_EXTRA_CA_CERTS (Node). One test request per image.

What the checkpoint does with each request

  1. Who: each agent has its own proxy login.
  2. Where: hostname checked against the allowlist before any DNS lookup (so <data>.evil.com can't leak through the proxy's own resolver). IP literals refused. Then resolve and deny private, link-local, loopback and metadata addresses. CONNECT host = TLS SNI = HTTP Host.
  3. Read it: TLS terminated; request body buffered with a max size; URL and header sizes capped; encodings normalized; every redirect re-checked.
  4. Keys: placeholders (gw_ph_openai_x7f3) swapped for the real key only on the right host; a placeholder anywhere else is a tripwire. On LLM hosts, any credential that isn't my placeholder is blocked, wherever it sits: Authorization, x-api-key, x-goog-api-key, api-key, query string, body.
  5. Provider-side tools: on LLM hosts, block request fields that make the provider fetch a URL for the agent (remote MCP server_url, web search tools, image_url / file URLs) unless the URL's host is on the agent's allowlist. Otherwise the provider becomes the exfil channel, paid with my key.
  6. Endpoint rules: method + host + path regex + max bytes. Writes are path-scoped (POST github.com/repos/me/*), so "post to the attacker's gist" is an unknown move.
  7. Budget: every outbound byte (URL + headers + body + WebSocket frames) counted per agent per destination. Unknown destinations: hard cap of N bytes/day.
  8. Unknown move: blocked with a 403 and a reason, sent to the reviewer. The reviewer can deny or escalate to me, and anything it allows still spends budget. It never overrides a hard rule. Request content is passed to it as quoted, truncated, redacted data.
  9. Responses: LLM hosts stream (SSE keeps working). Everything else is buffered and scored by PromptGuard 2 (chunked, 512 tokens per chunk) before the agent sees it. Flagged content puts the agent in strict mode: no reviewer allows, unknown = blocked.
  10. WebSockets: upgrade only to allowed hosts; frames counted and size-capped via mitmproxy's websocket_message hook.
  11. Record everything, redacted.

Learns, then locks: a short supervised run records each agent's normal moves; I approve them as its allowlist; after that, deny by default. Why Docker, not Linux users: users/groups are allow-by-default; mounts are deny-by-default, which matches the thesis.

12. Known limits (goes in the README)

  • A slow leak that fits inside an allowed endpoint's size cap and path rule gets through. It shows up in the bytes-out chart.
  • The reviewer reads attacker-controlled content, so it can be prompt-injected. That's why it never overrides hard rules and its allows still spend budget.
  • Reviewing a move sends a redacted, truncated copy of it to the Meta API.
  • Agents that pin certificates can't run behind it.
  • Files are protected by the mount policy, but individual reads and writes aren't logged.
  • v1 keys: static API keys and bearer tokens via env vars only.
  • Doesn't stop an agent being misled into a wrong answer, or leaking in its reply to me.
