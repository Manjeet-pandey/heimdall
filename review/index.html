      Heimdall

      A checkpoint between your AI agents and the internet.

      AI agents read things they can't trust (issues, web pages, email) while holding your real API keys. One hidden instruction can turn them against you. Heimdall assumes that will happen and controls the only way out.

      Built with Muse SparkMuse WonderPromptGuard 2Llama as the attacker

      Built solo by Manjeet during the Meta Global AI Developer Hackathon (Oct 28 – Nov 3, 2026) · Indie track · Push the Frontier

      How it works

      Every request leaves through one checkpoint

      Agentsealed sandbox
      no internet, no DNS      gw_ph_openai_x7f3

      Heimdallchecks · records · blocks
      hard rulesMuse SparkMuse Wonderunsure = deny
      →
      Internetonly allowed sitesreal key, right site only
      Placeholder keys

      The agent never holds a real key. Heimdall swaps it in only for the one site it belongs to, over https. A placeholder seen anywhere else is a tripwire.

      Hard rules first

      Allowed sites, no IP literals or private addresses, no other people's keys, no data smuggled through the AI provider, size caps and byte budgets.

      Muse reviews the rest

      Muse Spark judges anything new and reads every write against the agent's task and history. When Spark isn't sure, Muse Wonder decides.

      Fails closed

      If Meta's API is down, nothing new gets out. An unsure model means no.

      PromptGuard 2

      Scans what the agent reads. A hidden instruction puts the agent in strict mode: nothing new leaves without you.

      Every byte counted

      Each request is logged with its reason, and bytes out are counted per agent and destination.

      What still gets through

      A secret split into tiny pieces, inside the size limits, across normal-looking comments on an allowed site. Heimdall doesn't stop that yet, but it counts and charts every piece, so you can see it happen.
